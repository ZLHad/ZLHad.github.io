## 问题在哪

生成式 AI 的回答是一个 token 一个 token 产生的，所以用户感受到两种时延：第一个 token 什么时候出现（TTFT），后面每个 token 要等多久（TPOT）。多数卸载研究把请求当作比特流，只做本地还是远端的选择，这样就看不到提示词长度如何同时影响两种时延，也看不到一段很长的图像或视频提示里有多少是冗余的。

在没有基站的偏远地区，这个选择很实际。无人机上的小模型回答快，质量偏低；低轨卫星上的完整基础模型回答好，但更晚；而一架无人机只能缓存少数几个模型。

## 关键想法

把一切都看成 token。一个连续的比率 η 压缩整段输入，因此它同时决定上行负载和 prefill 工作量，也就决定了 TTFT。压缩有质量代价，调度器可以给这个代价定价。

<Eq tex="\tilde n_u^{\rm in}=\eta_u\,(n_u^{\rm txt}+n_u^{\rm vis}),\qquad \eta_u\in[\eta_{\min},1]" note="一个比率压缩全部输入，同时决定链路上的负载和 prefill 的工作量。" />

第一个 token 要串行穿过整条链路。后面的 token 以流水线方式传输，速度取决于最慢的一环。

<Eq tex="\mathrm{TTFT}_u=T^{\rm G2A}_{u\to k}+T^{\rm A2G}_{k\to u}+(1-x_u)\mathrm{TTFT}^{\rm UAV}_u+x_u\left[T^{\rm A2S}+T^{{\rm ISL},\uparrow}+\mathrm{TTFT}^{\rm sat}_u+T^{{\rm ISL},\downarrow}+T^{\rm S2A}\right]" />

<Eq tex="\mathrm{TPOT}_u=\begin{cases}\max\{\overline{\mathrm{TPOT}}^{\rm UAV}_u,\;T^{\rm A2G}_{k\to u}\}&x_u=0\\ \max\{\overline{\mathrm{TPOT}}^{\rm sat}_u,\;T^{{\rm ISL},\downarrow},\;T^{\rm S2A},\;T^{\rm A2G}\}&x_u=1\end{cases}" note="首 token 时延是串行求和，逐 token 时延是流水线瓶颈。" />

<Eq tex="\mathrm{QoE}_u=w_q\ln(1+Q_u)-w_1\,\mathrm{TTFT}_u-w_2\,\mathrm{TPOT}_u" note="质量收益是凹函数，边际递减，再减去两种时延的惩罚。" />

## 系统怎么运转

三层网络，两个时间尺度。每 120 秒，知识驱动的规划器根据近期需求提出无人机部署和模型缓存的候选方案，用快速调度器推演打分，再做交替搜索。每个 2.4 秒的时隙，条件扩散 TD3 调度器（CD-TD3）为每个用户选择卸载层和压缩率，带宽和算力由闭式规则分配。

## 结果

评估是仿真：5 架无人机、30 个用户、6 颗卫星、10 个无人机侧模型，解码开销按 NVIDIA Jetson AGX Thor 的速率设定，质量系数来自模型卡。结果在 30 个留出配置上统计。所提框架的人均 QoE 最高，**比 TD3 高 31.9%，比 Greedy 启发式高 69.2%**。
